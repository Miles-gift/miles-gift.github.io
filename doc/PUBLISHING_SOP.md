# yoyo的旅行日记：日常发布 SOP

本流程用于将本地 Markdown 安全发布到 `https://miles-gift.github.io/`。公开站点是静态站，内容不会从浏览器直接写回 GitHub；本地工作台负责编辑与预检，GitHub Actions 负责构建和上线。

## 1. 开始前

1. 在项目根目录更新依赖：`pnpm install --frozen-lockfile`。
2. 启动工作台：`pnpm cms`，访问 `http://localhost:5188/`。
3. 如需并排看完整站点，再执行 `pnpm dev`，访问 `http://localhost:4321/`。
4. 开始编辑前先执行 `git status --short`，确认已有修改的归属，避免覆盖尚未提交的工作。

## 2. 创建与编辑

1. 选择正确类型：长篇札记、原文资料、灵光便笺或旅程。
2. 新建内容时先保持草稿状态。
3. 标识创建后不在工作台中改名：普通内容使用小写英文、数字和连字符；灵光便笺使用 `YYYYMMDD-001`。
4. 填写标题、描述、日期、主题和标签；资料库中的本人笔记选择 `personal-note`，此时来源网址和核心收获可以留空。
5. 直接粘贴本人的 Markdown 原文；除错别字、格式和隐私清理外，不代替原文总结或重写。
6. 图片只通过上传按钮加入。填写能表达图片内容的替代文本，不用“图片”“截图”等无信息描述。
7. 保存后检查实时预览，尤其是标题层级、列表、表格、代码块、公式、链接和图片。

## 3. 公开边界复核

公开前逐项确认：

- 没有 `/Users/...`、`file://`、Windows 盘符等本地路径。
- 没有证书原图、二维码、学号、证书编号、手机号、精确住址或账号密钥。
- 没有未经许可的队友、老师或其他第三方姓名与个人信息。
- PDF、Word、Excel、PPT、压缩包等附件已移除，或确实拥有公开授权。
- 获奖与旅程只陈述已确认事实，不从证书名称反推个人职责或贡献。
- 外部资料填写完整来源链接；个人原始笔记不伪造来源或总结。

## 4. 发布预检与本地构建

1. 将可见性改为 `public`，保存。
2. 点击“发布预检”。错误必须全部修复；警告必须逐条人工判断。
3. 在项目根目录执行 `CI=true pnpm build`。
4. 构建必须同时通过内容预检、Astro 静态生成和 Pagefind 搜索索引。
5. 打开本地站点，至少检查新内容详情、所属列表、搜索结果、归档和一个窄屏视口。

草稿必须保持 `draft=true` 与 `visibility=draft`，构建后不应出现在列表、搜索、归档或生成页面中。

## 5. Git 与上线

1. 用 `git diff --check` 检查空白错误。
2. 用 `git diff --stat` 和 `git status --short` 确认只包含本次发布内容。
3. 提交并推送到 `main`；大型改动先在 `codex/` 功能分支验证，再快进合并。
4. 在 GitHub Actions 中等待自定义的 “Deploy to GitHub Pages” 工作流成功。GitHub 自动生成的旧 Pages 工作流不是本项目的发布依据。
5. 打开线上详情页、所属列表、首页入口和搜索，确认最新内容可见且无样式错误。
6. 执行 `git fetch origin`、确认本地 `HEAD` 与 `origin/main` 一致，再执行 `git pull --ff-only` 验证没有遗漏。
7. 更新根目录 `README.md` 的阶段记录、提交、标签、Actions 和线上验证结果。

## 6. 发布节奏建议

- 灵光便笺：形成一个独立观点即可发布，不强行扩成长文。
- 长篇札记：完成结构、事实、隐私、移动端与链接检查后发布。
- 原文资料：保留原始笔记组织，按学习进度更新 `lastReviewedAt`。
- 旅程：只在事实、日期与公开边界确认后更新。
- 每季度运行一次内容健康检查，合并过细标签、复核失效链接和长期未维护资料。

故障、冲突和回滚步骤见 [CMS 恢复手册](CMS_RECOVERY.md)。
