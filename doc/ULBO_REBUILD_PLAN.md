# 依据 Ulbo 模板重构「yoyo的旅行日记」：分阶段执行方案

> 编制日期：2026-09-25  
> 状态：执行中；阶段 0、1、2 已完成
> 实施范围：现有 Astro 网站的视觉、页面、阅读体验、内容发现与发布链路适配

## 1. 背景与目标

本方案以 [Ulbo 的 Astro 主题页](https://astro.build/themes/details/ulbo/)、[在线演示](https://template.ulna520.top/)和[源码仓库](https://github.com/xxy1103/ulbo-astro-theme-template)为参考。Ulbo 提供电影感首屏、统一的明暗主题、页面过渡、长文阅读工具、标签探索及快捷搜索。其公开源码目前以 Astro 6、npm 和单一博客内容集为基础；本站当前使用 Astro 7、pnpm 和四类内容集。因此，推荐以现有网站为主工程，逐项移植并适配 Ulbo 的视觉与交互，而不直接以模板仓库覆盖现有项目。

重构完成后，访客从首页到文章、资料库、旅程和关于页，应获得连贯的 Ulbo 风格体验；现有内容、网址、本地编辑工具和发布流程应继续可用。

### 1.1 现站基线

- 站点身份以 `src/config.ts` 当前配置的「yoyo的旅行日记」为准；较早文档中的「Miles」描述需要在实施时核对并校正。
- 当前公开内容共 37 条：4 篇文章、9 条资料、3 条短想法、21 条旅程记录。内容由 `src/content.config.ts` 中的 Astro Content Collections 管理。
- 五项主导航为「首页／文章／资料库／旅程／关于」；归档、标签、主题及搜索提供辅助浏览入口。
- 现有全站搜索使用 Pagefind；本地 yoyo Studio 管理四类内容；GitHub Actions 构建后发布至 GitHub Pages。
- 现站已经具备明暗主题、部分页面过渡、目录、Markdown 扩展、图片查看、SEO 信息和公开产物检查。阶段 0 应逐项核实功能现状，避免重复实现。

### 1.2 默认设计与技术决定

1. **视觉方向**：较高程度还原 Ulbo 的首屏尺度、排版节奏、明暗主题和阅读体验，同时继续使用本站真实内容与品牌文案。
2. **工程方向**：保留 Astro 7、pnpm、现有 Content Collections 和 GitHub Pages 构建链路；按兼容性移植模板组件与样式。
3. **内容方向**：保留四类内容各自的字段、URL 和展示意义，不将资料、短想法或旅程强行改写为普通博客文章。
4. **搜索方向**：先在现有 Pagefind 索引上实现模板式搜索交互和 `Cmd/Ctrl + K` 快捷入口；仅在实际效果更好时考虑更换底层搜索。
5. **RSS 边界**：Ulbo 提供 RSS，但本站当前信息架构已明确移除。默认沿用现站决定；若需恢复 RSS，应在方案确认时提出。

## 2. 页面与功能映射

| Ulbo 页面或能力 | 本站落点 | 适配要点 |
| --- | --- | --- |
| 首页沉浸式 Hero、概览和最近更新 | `/` | 采用模板的首屏尺度和页面节奏；概览展示真实的四类内容与精选入口 |
| Blog 列表 | `/articles/` | 长文为主列表；短想法保留独立形式及明确入口 |
| Archive | `/archives/` | 统一视觉，保留按年份、类型和主题筛选 |
| Tags 探索 | `/tags/`、`/topics/` | 借鉴模板的筛选及反馈，适配现有标签与受控主题 |
| About | `/about/` | 使用模板的人物介绍节奏，呈现现有真实简介和旅程入口 |
| 文章阅读页 | `/articles/<slug>/` | 统一 Hero、元信息、目录、正文与阅读工具 |
| 模板快捷搜索 | 搜索层和 `/search/` | 保留四类内容的全站索引，增加快捷键与键盘操作 |
| 模板单一文章模型 | 四类 Content Collections | 沿用各类 schema、详情页及发布规则 |

## 3. 分阶段执行

各阶段按顺序实施。每阶段完成后记录实际改动、验证结果及与计划的偏差，再进入下一阶段；若发现内容或网址回归，先修复回归。

### 阶段 0：固定基线，形成逐项迁移清单

**目标**：建立可以量化对照的改造前状态。

**任务**

1. 在独立 `codex/` 分支实施，记录当前提交、依赖版本和公开路由。
2. 记录 37 条内容的文件位置、slug、公开状态和生成网址；抽样保存首页、五个主栏目及各类详情页的桌面和手机截图。
3. 执行现有质量命令，记录类型检查、内容校验、构建、站内链接、站点地图、搜索索引和关键资源体积。
4. 固定本次参考的 Ulbo 源码版本，建立组件差异表：直接可借鉴、需要适配、本站已有等价实现、与现站需求不符。
5. 对照现行 README 与旧设计文档，标出站点名称、栏目和发布规则的过时描述。

**交付物**：改造前基线、路由与内容清单、Ulbo 功能差异表。

**通过条件**：每条现有公开内容都有明确去向；能够在后续阶段判断是否发生内容丢失、网址失效或资源体积异常。

### 阶段 1：定稿视觉规范与页面线框

**目标**：让模板风格适配本站的中文内容和四类信息层级。

**任务**

1. 从 [Ulbo 样式源码](https://github.com/xxy1103/ulbo-astro-theme-template/blob/main/src/styles/global.css)提取浅色、深色、字体、宽度、间距、圆角与动效规则，整理为本站设计令牌。
2. 以模板现有色值作为视觉起点：浅色背景 `#F4F5F6`、白色表面 `#FFFFFF`、深色背景 `#0F1117`、浅色主题强调蓝 `#2337FF`、深色主题强调蓝 `#7B8CFF`。正文与重点文字的对比度在中文排版样张中校准。
3. 对照模板的 Outfit、Plus Jakarta Sans 与本站现有字体，制作中英混排样张，确定标题、正文、导航和代码的字体职责；核对本地托管后的体积。
4. 绘制桌面、平板和手机线框：全局导航、首页、列表、详情、搜索、空结果和 404。
5. 定义动效规则：页面过渡用于导航反馈，交互动画说明状态变化；检查键盘操作和系统“减少动态效果”设置。

**交付物**：视觉令牌、页面线框、典型页面样张和组件清单。

**通过条件**：四类内容能凭标题、元信息和布局分辨；中文长段落、代码及窄屏表格保持可读。

### 阶段 2：接入全站布局

**目标**：建立所有页面共享的视觉与交互基础。

**任务**

1. 改造 `src/layouts/Layout.astro`、全局样式、`src/components/Header.astro` 和页脚，统一明暗主题、页面宽度、导航与焦点样式。
2. 将 Ulbo 的 Hero、章节标题、列表项和搜索入口等模式整理为可复用组件，减少各页面分别维护的 CSS。
3. 保留现有五项主导航，安排搜索、归档、标签和主题的辅助入口。
4. 检查页面过渡后的主题状态、菜单开合、滚动位置与事件绑定，防止重复监听或切页后控件失效。
5. 核对品牌标识、favicon、分享图与模板视觉之间的协调性，保留本站身份信息。

**交付物**：所有页面可共用的新布局和组件。

**通过条件**：任意页面均可切换主题与导航；桌面和手机菜单可用；键盘焦点清晰；控制台无新增错误。

### 阶段 3：首页与栏目入口

**目标**：把模板的页面节奏应用到本站真实内容。

**任务**

1. 重排 `src/components/home/HomePage.astro`：个人介绍与主视觉、精选文章、最近更新、资料入口、短想法、旅程入口和关于说明。所有数量及条目直接来自公开内容集。
2. 重构文章列表，让长文与短想法有清楚的视觉层级和到达路径。
3. 重构资料库，保留资料类型、学习状态、主题及原始笔记的含义。
4. 重构旅程列表，突出实际发生时间和内容类别，避免将经历压成普通博客文章卡片。
5. 同步更新关于、归档、标签与主题页的标题、筛选控件、结果状态和空状态。

**交付物**：可完整浏览的首页和全部栏目入口。

**通过条件**：导航可到达各类内容；列表数量与公开内容一致；筛选结果和网址参数正确；空结果能引导访客继续浏览。

### 阶段 4：详情页与长文阅读

**目标**：统一阅读体验，同时保留每种内容的语义。

**任务**

1. 统一文章详情页的标题区、发布日期与更新日期、阅读时长、标签、目录和相关内容。
2. 使用现有 Markdown 内容逐类核对标题、引用、图片说明、代码块、复制按钮、表格、数学公式、图表与站内链接；现有 Typst 和提示框等自定义处理纳入回归检查。
3. 为资料详情保留来源、状态和原文展示；短想法保留简短阅读节奏；旅程详情保留时间精度与事实描述。
4. 调整目录在桌面长文中的跟随行为和手机端的展开方式，适配图片灯箱及打印样式。
5. 用真实文章和资料逐屏检查中文换行、超宽代码、表格、竖图及锚点位置。

**交付物**：四类详情页和可复用的正文样式。

**通过条件**：现有 Markdown 内容及语义完整；目录锚点、代码复制、图片查看与打印可以实际操作。

### 阶段 5：搜索、标签与交互

**目标**：让访客跨四类内容快速发现所需条目。

**任务**

1. 在现有 Pagefind 索引上实现模板风格的搜索层和 `Cmd/Ctrl + K` 快捷入口，保留完整搜索页。
2. 为搜索结果标明内容类型，并确保结果直达正确的文章、资料、短想法或旅程页。
3. 加强标签与主题页的筛选、结果计数、重置和无结果反馈。
4. 检查搜索层与移动菜单的焦点进入、`Esc` 关闭、关闭后焦点返回，以及页面切换后的再次使用。
5. 对比 Ulbo 的 Fuse.js 与本站 Pagefind 在索引范围、搜索效果和产物体积上的实际表现；只有明确获得更好结果才更换底层搜索。

**交付物**：全站搜索、标签探索及交互说明。

**通过条件**：四类公开内容均可检索；键盘和触控操作可完成搜索；草稿和非公开内容不进入结果。

### 阶段 6：内容工作台、SEO 与构建衔接

**目标**：保证重构后的站点仍可日常编辑、构建与发布。

**任务**

1. 保持 `src/content.config.ts` 与 yoyo Studio 的创建、编辑、图片处理和发布预检字段一致；主题新增展示字段设定明确默认值。
2. 逐类检查草稿、`visibility`、精选内容、封面及缺图状态，确保首页、列表、详情、搜索和站点地图采用同一公开规则。
3. 复核 canonical、描述、分享图、结构化数据、robots、sitemap 和旧 `/blog/<slug>/`、`/archive/` 兼容路径。
4. 更新受此次重构影响的构建检查脚本、发布说明和设计文档。
5. 记录引入的 Ulbo 源码、素材及相应许可信息；模板仓库采用 [MIT 许可证](https://github.com/xxy1103/ulbo-astro-theme-template/blob/main/LICENSE)。

**交付物**：可继续日常发布的站点与工作台，以及更新后的维护文档。

**通过条件**：通过 Studio 新建并预检各类内容后，站点仍能正确生成；既有 37 条内容和公开网址保持可访问。

### 阶段 7：全面验收与交付

**目标**：以可复核的证据交付重构成果。

**任务**

1. 执行 `CI=true pnpm quality`，覆盖类型检查、内容校验、生产构建、Pagefind 与公开产物检查；在隔离环境运行 CMS 冒烟流程。
2. 检查首页、每类列表与详情、标签、主题、归档、搜索、关于、404 及旧网址兼容页。
3. 至少在 390px 手机、768px 平板和 1440px 桌面宽度检查浅色与深色，复核横向溢出、菜单、目录、筛选和搜索。
4. 用键盘走通主要路径，检查可见焦点、标题层级、图片替代文本和减少动态效果。
5. 对比阶段 0 的截图与资源体积；修复可见回归，随后提交代码、变更摘要和验证记录。

**交付物**：可审阅的重构代码、页面截图、验收记录及剩余问题清单。

**通过条件**：质量命令通过；37 条既有内容可访问；核心路由和旧链接有效；四类内容可搜索；CMS 发布流程可用；桌面与手机端无关键视觉或交互问题。
