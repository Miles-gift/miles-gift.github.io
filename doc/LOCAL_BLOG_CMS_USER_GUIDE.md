# 本地博客 CMS 使用手册

CMS 只在当前电脑运行。文章和博客设置先保存在仓库忽略的 `.local-cms/` 工作区；按下“检查并发布”后才会写入 GitHub `main`。部署仍由 GitHub Actions 完成。

## 启动与停止

在仓库根目录打开终端：

```sh
npm ci
npm run cms
```

第一次运行 `npm ci`；之后直接运行 `npm run cms`。终端会显示 `http://127.0.0.1:4178/`，在本机浏览器打开该地址即可。需要换端口时可运行 `CMS_PORT=4179 npm run cms`。按 `Ctrl+C` 停止 CMS；本地预览服务也会一起关闭。

CMS 只监听 `127.0.0.1`，不要将它改成监听公网地址，也不要把 `.local-cms/` 草稿目录提交到 Git。

## 新建和编辑文章

1. 在“文章”页选择“新建文章”，填写标题、发布时间、分类、标签和正文。新建文章默认是私有草稿，slug 保存后固定。
2. 日期按 `Asia/Shanghai` 输入。正式文章要设置一个分类和至少一个标签；草稿可暂时不填分类和标签。
3. “保存到本机”只写入 `.local-cms/`，不会更新公开网站。文章列表中的“本机已保存”和“加入发布清单”是不同状态。
4. 已发布文章可以在编辑器中修改标题、日期、摘要、正文、分类、标签和封面；slug 保持不变。保存前可查看正文对比，也可用“预览文章”打开真实 Astro 页面。
5. 图片通过“上传封面”或“上传并插入图片”添加。支持 PNG、JPEG、WebP；CMS 会优化后保存在本地媒体工作区，只有被准备发布的文章或设置引用的图片才会上传。

### 草稿和发布清单

- 私有草稿默认不公开。保持“保存为草稿”勾选，并确保“加入发布清单”未勾选。
- 要发布文章，先取消“保存为草稿”，补齐正式文章必填字段，再勾选“加入发布清单”并保存。
- “加入发布清单”只选择文章；博客设置的已保存改动会随发布一起列出。
- 列表中的“删除文章”会再次确认。已发布文章会先标为“待删除”，可以从列表点“恢复”；实际删除只在确认发布并推送后发生。未发布的新草稿在确认删除后会从本地草稿库移除。
- 发布删除会让文章 URL 失效。需要保留旧链接时，发布前先在其他位置设置合适的跳转。

## 编辑博客页面文案

进入“博客设置”可修改站点名称、站点摘要、博客 Hero 标题/副标题/背景图、归档标题与介绍、空状态文案和默认文章 Hero 背景图。归档介绍支持 `{total}`、`{current}`、`{last}` 动态值。保存到本机后可按“预览博客页”查看真实页面；保存设置不会立即更新线上网站。

## 检查并发布

发布前确认以下条件：

- 已切换到 `main` 分支，`origin` 指向 `Miles-gift/miles-gift.github.io`。
- Git 工作区没有其他未提交文件，本地 `main` 没有尚未推送的提交；GitHub 凭据可用。
- 文章已加入发布清单且不是草稿；没有未解决的源文件冲突。

在“发布”页复核变更清单，选择“检查并发布到 main”。CMS 会再次确认，然后 fetch 远端、校验和构建、精确暂存清单内文件、提交并推送。过程不使用强推，也不会把未选的私有草稿或无关文件一起提交。页面会显示 GitHub Actions 链接和线上检查状态。

CMS 仅允许从 `main` 发布。它追踪项目的 Astro GitHub Pages 工作流（`.github/workflows/deploy.yml`）和线上页面检查；GitHub 另行触发的 Jekyll 检查不代表 Astro 站点部署结果。处于功能分支、仓库有无关改动或远端存在无法快进整合的提交时，发布按钮会停用并说明原因。处理好 Git 状态后重新打开发布页即可。

## 失败处理与恢复

- **校验、测试或构建失败**：CMS 会撤销本次写入的源文件，保留 `.local-cms/drafts/` 中的编辑和 `.local-cms/backups/` 备份。修复内容或代码后再试。
- **远端领先**：CMS 只尝试 `--ff-only` 快进。若涉及的文件无法安全同步，先手动 fetch 并处理冲突；不要用强推覆盖远端。
- **GitHub 拒绝推送**：本地提交会保留，草稿工作区也会保留。先看 `git status` 和 `git log -1 --oneline`，同步远端并解决后再继续；不要重复创建相同内容的提交。
- **查看本地备份**：运行 `ls -lt .local-cms/backups`，再查看对应目录的 `manifest.json`。备份文件位于同一目录下的 `files/`，按清单逐个复制回对应仓库路径。
- **查看已成功推送的编辑副本**：`.local-cms/archive/<提交 SHA 前 12 位>/` 保存了本次发布的本地草稿副本和提交 SHA。
- **手工修改文章**：CMS 会在发布前比较源文件哈希。若源文件在打开文章后被其他编辑器改动，先复制需要保留的文本、关闭编辑器并重新读取最新源文件，再手动合并；CMS 不会覆盖冲突。

## GitHub Pages 与内容安全

部署是否完成以发布页显示的 GitHub Actions 和线上检查为准。Git push 成功表示提交已到 GitHub，不代表网站已经构建完成。私有草稿保存在本机，但已发布到公开站点或 GitHub 的内容会成为公开历史；发布前请确认内容和图片可以公开。

CMS 与 GitHub Actions 发布流程不自动管理 GitHub Pages 仓库设置。如果 Pages 尚未配置为 GitHub Actions 来源，请在 GitHub 仓库 Settings → Pages 中选择相应来源。
