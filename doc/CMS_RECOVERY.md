# yoyo Studio：故障处理与恢复手册

## 保存提示版本冲突

原因：编辑页打开后，同一 Markdown 文件被工作台、编辑器或 Git 操作更新。工作台拒绝用旧版本覆盖新内容。

处理：

1. 先把当前编辑框中尚未保存的正文复制到临时文本中。
2. 刷新编辑页，读取磁盘上的最新版本。
3. 人工比较并合并两份内容，不要强行覆盖。
4. 重新保存、运行发布预检和完整构建。

## 字段校验失败

- 标识无效：普通内容只用小写英文、数字和连字符；随想使用 `YYYYMMDD-001`。
- 草稿状态冲突：`visibility=draft` 必须同时对应 `draft=true`；界面会自动同步。
- 分类无效：从工作台提供的受控词表中选择，不手写新的分类值。
- 外部来源无效：`external` 资料必须填写完整 `http(s)` 地址；本人原始笔记改用 `personal-note`。
- 图片缺替代文本：补充一条能表达图片信息的描述。
- 出现本地绝对路径：删除或改成站点内 `/media/...` 路径。

## 图片上传失败

1. 确认文件是真实 PNG、JPEG、WebP 或 AVIF，而不只是修改了扩展名。
2. 确认文件不超过 8 MB，输入图像总像素没有异常。
3. SVG、GIF、PDF 和 Office 文件不会被接受；先在可信工具中导出为静态图片。
4. 重启 `pnpm cms` 后重试；仍失败时记录终端中的错误信息，不要把原文件直接复制到公开目录绕过检查。

## 误删内容

工作台删除是可恢复操作，正文和关联图片会移到 `.trash/cms/<时间>/`，界面会显示恢复位置。

1. 立即停止创建同标识内容，避免路径冲突。
2. 在 `.trash/cms/` 中找到最近时间目录。
3. 将 `articles/<slug>/` 或 `<kind>/<id>.md` 移回原来的 `src/content/` 位置。
4. 如存在 `media/<kind>/<id>/`，移回 `public/media/<kind>/<id>/`。
5. 执行 `pnpm validate:content` 和 `CI=true pnpm build`。

若回收区已被清理，从 Git 恢复最后一次已提交版本，再手工补回未提交内容。不要使用会覆盖整个工作区的破坏性恢复命令。

## 构建失败

1. 从第一条错误开始处理，不被后续连锁错误干扰。
2. 内容错误先运行 `pnpm validate:content`，按文件和字段修正。
3. 工作台错误依次运行 CMS 构建、TypeScript 检查和冒烟测试。
4. 如果本地通过、Actions 失败，核对 Node/pnpm 版本、大小写文件名、未提交文件和绝对路径。
5. 修复后重新执行完整构建并提交；不要跳过失败工作流直接声明上线完成。

## 推送冲突或远端领先

1. 执行 `git fetch origin`，检查本地与 `origin/main` 的差异。
2. 保存当前未提交修改，再用普通合并或变基解决冲突。
3. 逐个打开冲突文件，保留双方真实内容；不要用整仓覆盖方式解决。
4. 重新执行内容预检、构建和相关测试后再推送。

## 线上内容错误或需要回滚

优先采用可审计的“反向提交”：

1. 确认出错的提交和受影响页面。
2. 对该提交创建反向修改，或恢复到最近的阶段标签后形成一个新提交。
3. 本地完整构建并检查关键页面。
4. 推送后等待 “Deploy to GitHub Pages” 成功，并复核线上页面。

阶段基线标签用于定位稳定版本，不代表可以跳过对用户新内容的备份。若只是一篇文章的事实或隐私问题，可先把它改为草稿并发布，再进行完整修订。
