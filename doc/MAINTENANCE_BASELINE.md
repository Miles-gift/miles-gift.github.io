# 阶段 8：长期维护基线

> 建立日期：2026-09-11
> 范围：内容健康、资料复核、外链可用性与定期自动检查

## 1. 目标

让网站在首发之后仍然容易维护：内容增长时能看见类型和主题是否失衡，资料变旧时能得到复核队列，外部来源失效时能在日常浏览发现之前收到自动检查结果。

## 2. 实施计划

1. 从四个正式内容集合生成确定性的健康报告。
2. 把无网络依赖的健康检查加入每次 `pnpm quality`。
3. 独立检查公开 Markdown 中的真实外链，区分确定失效与暂时网络异常。
4. 通过 GitHub Actions 每周自动执行完整质量门禁、内容健康和外链检查。
5. 不在本阶段引入访客追踪、评论账号、远程后台或对象存储，保留现有公开数据边界。

## 3. 已实现

### 3.1 内容健康报告

`pnpm content:health` 会检查并输出：

- 四类正式内容的总数、公开数与草稿/非公开数。
- 公开内容的主题分布及尚未使用的受控主题。
- 公开资料是否具有有效的 `lastReviewedAt`。
- 超过 180 天未复核的资料队列。
- 只出现一次的标签，作为合并近义词或继续积累的整理提示。

`pnpm content:health:write` 会用同一口径更新 [内容健康报告](CONTENT_HEALTH_REPORT.md)。缺失或无效的资料复核日期会使检查失败；资料变旧和单次标签只形成维护提示，不阻塞正常发布。

### 3.2 外链巡检

`pnpm check:external` 扫描 `src/content/` 内全部 Markdown 的 HTTP(S) 链接并去重：

- 2xx 与 3xx 视为正常。
- HEAD 不被支持、服务器限流或暂时失败时，会再用轻量 GET 请求复核。
- 明确返回 404 或 410 才判定为失效并使检查失败。
- 403、429、5xx、超时和网络错误显示为提示，避免一次外部波动造成错误删除或误判。
- 报告失效链接时同时列出所在内容文件，便于直接维护原文。

首轮巡检发现 PyTorch 原始笔记中的 `TransformerDecoder` 教程子页返回 404；已只替换该链接为 PyTorch 官方文档，表格文字与其余 Markdown 原文未改写。修复后 51 个唯一外链全部正常。

### 3.3 定期检查

`.github/workflows/content-health.yml` 会在相关脚本、依赖或内容进入 `main` 时执行；此外每周一 00:30 UTC（北京时间 08:30）定期运行，也支持在 GitHub 手动触发。任务依次运行：

1. 安装锁定版本的依赖。
2. 执行完整本地质量门禁。
3. 输出内容健康结论。
4. 访问并检查公开内容外链。

工作流权限只有 `contents: read`，不会自动修改仓库、创建 Issue、发布评论或向第三方写入数据。

## 5. 日常使用

编辑内容后：

```bash
pnpm validate:content
pnpm content:health
CI=true pnpm quality
```

需要更新仓库内健康快照时：

```bash
pnpm content:health:write
```

需要即时检查外链时：

```bash
pnpm check:external
```

## 6. 公开边界与后续项

本阶段没有新增 Cookie、访问统计、访客身份收集或远程写入。以下能力需要真实内容、账号权限或隐私选择，继续保留为后续决策项：

- 在线远程 Studio 与登录授权。
- 评论或反馈系统及审核方式。
- 隐私友好统计及是否需要 Cookie/公开说明。
- 对象存储、媒体删除与备份策略。
- 多语言、Webmention、newsletter 和联合发布。
- 有足够真实案例后再建立项目独立栏目。

在上述选择明确前，不使用占位链接或未经授权的第三方服务填充功能。
