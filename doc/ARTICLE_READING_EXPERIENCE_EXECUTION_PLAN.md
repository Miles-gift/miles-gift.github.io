# 文章阅读体验改造执行方案

> 编写日期：2026-09-26
> 目标：让 ulBo 个人博客的长文滚动自然、正文排版耐读、字体与链接样式统一，并保留技术内容的完整表达。
> 当前状态：**主要代码改造已完成并进入功能分支；生产构建、检查和两篇样本的视觉复查通过。滚动性能的前后 Performance trace 尚未采集，见文末实施记录。**
> 主要范围：`/blog/<slug>/` 的阅读区；共享字体令牌会影响首页、归档、标签、关于与导航，需要同步校对。
> 方案依据：本仓库源码、两篇现有公开文章、本地 Astro 预览的视觉与 DOM 检查。

## 1. 设计对象与目标体验

这是 yoyo 的个人博客，内容横跨集成电路学习、电子科学技术和个人学习记录。读者可能连续阅读技术步骤、代码、公式、截图，也可能阅读篇幅很长的中英文材料。网站的主要任务是让读者**持续阅读、定位章节、理解资料来源，并能返回原处**。

本次把文章视为一份经过细心编排的个人研究笔记：界面保留现有芯片图像 Hero 和冷色调身份，正文像清晰的实验记录，精度来自字距、层次、留白和定位反馈，而非额外堆叠装饰。文章内容原文、标题层级和技术图像不因视觉改造而删减。

### 1.1 用户感知目标

1. 滚轮、触控板、触摸拖动保持浏览器原生手感；只在明确点击目录或正文锚点时出现短而可中断的定位滚动。
2. 进入正文时没有整块文章的漂浮或等待感；长文连续滚动时不出现明显的卡顿、图片造成的突跳或目录反复抖动。
3. 一屏文字的行长、字号和行距使中文技术叙述与英文材料都容易追行；标题、列表、引语、代码、表格和图片形成一套语法。
4. 内链、外链、页内锚点和下载链接各有可辨认的含义；键盘、触摸和打印状态与视觉状态一致。
5. 深浅主题、桌面与手机、文章页与共享 UI 的字体气质相同，排版不会因为字体加载产生明显位移。

### 1.2 工作边界

- 改造重点是文章阅读，不重新设计首页 Hero、导航结构、文章内容、搜索算法或 CMS。
- 允许为字体统一调整全站共用令牌及少量组件覆写；不把全文改成新的内容格式，也不引入滚动动画库。
- 保留现有目录、搜索落点、灯箱、代码复制、Mermaid、KaTeX、PDF 导出、Astro ClientRouter 和历史滚动恢复。
- 对页面转场可以做文章页的局部简化，但不能破坏其他页面的现有导航反馈。

## 2. 已确认的现状与证据

### 2.1 文件与渲染路径

### 2.2 当前视觉与性能相关事实

1. `global.css` 顶部通过 Google Fonts `@import` 加载 Outfit 与 Plus Jakarta Sans；标题使用 Outfit，正文使用 Plus Jakarta Sans，中文主要依赖系统字体回退。代码字体在 CSS 中声明了 JetBrains Mono 等回退，但仓库没有自托管字体文件。
2. `.prose` 为 `1.05rem / 1.8`，直接子节点大多限制 `72ch`；桌面文章卡片所在网格最大宽度为 1400px，右栏 260px、间距 60px。阅读列与宽媒体的关系需要重新梳理。正文目前继承全局蓝色链接，外链没有专门的样式或来源提示。
3. `body` 锁定滚动，`#main-content` 使用 `100dvh`、`overflow-y:auto` 和全局 `scroll-behavior:smooth`。目录脚本又对点击目标显式使用原生 `scrollTo({ behavior:'smooth' })`；这是两套范围不同的平滑规则，需统一。CSS 的 smooth 不控制用户滚轮/触摸手势，主要影响程序化或锚点滚动，不能把它直接认定为手势卡顿原因。
4. `.content-card` 入场时对**整个文章卡片**做 `translateY + opacity` 动画，且 `will-change: transform, opacity` 长期保留。对极长文章，这属于应优先通过性能记录验证的绘制/图层成本假设；目前没有足够证据宣称它是唯一卡顿原因。
5. 目录子项用 `max-height: 0 → 1000px` 展开，活动章节变化会触发布局动画；目录脚本会随滚动更新活动项，也会在图像加载、字体就绪、窗口变化与 `ResizeObserver` 回调后重新测量标题位置。
6. 正文图片有阴影、悬停位移，暗色模式统一叠加 `brightness(0.6) contrast(1.2)` 滤镜；表格、代码块也有悬停效果。大图多的文章应在真实滚动轨迹中验证这些绘制效果的成本。
7. 现有正文第一个 Markdown 标题会与 `.prose h1/h2 { margin-top: 2.2em }` 叠加卡片内边距，预览首屏可见偏大的无信息空白。文章 Hero 已承担标题与元信息，阅读区开头应更快进入正文。
8. 打印/PDF 专用规则集中在 `BlogPost.astro`，使用独立的宋体回退与标题编号；任何正文 CSS 重构必须检查打印规则优先级、图片等待和分页结果。

## 3. 两轮设计推敲

### 3.1 第一轮概念：冷静的技术阅读页

- **色彩**：延续现有蓝色与芯片 Hero，使用偏蓝的中性底色、干净的正文表面、深墨色文字与一枚精确的蓝色强调色。
- **字体**：为拉丁字母与中文选择笔画密度相近的两套无衬线字体；代码保留真正的等宽字。
- **布局**：正文采用稳定的单一阅读轴，代码、图像、表格在需要时略宽于段落；右侧目录是导航仪表，不作为第二条正文栏。
- **动效**：只保留由用户触发的定位、复制、展开反馈；正文随滚动保持静止。

第一轮的风险是“冷色科技风”很容易变成普通蓝灰 SaaS 页面，或者用数字刻度、细线与指示灯堆出伪仪表感。本站既有大图 Hero 和真实的实验截图已提供个性，正文无需再造一套装饰系统。

### 3.2 修订后的设计方向：有精度的个人研究笔记

**视觉记忆点只放在阅读定位上**：目录当前章节用一条短而稳定的蓝色指示线；正文内链与外链用同一套下划线系统，并仅给真正跨站的链接一个小型“离站”符号。其余地方依靠排版比例和留白体现质感。页面不加全大写 eyebrow、装饰性编号、通用卡片阴影或逐段入场效果。

#### 基础色板（计划值，实施时用对比度与截图微调）

| 名称 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 雾蓝底 `canvas` | `#F3F6F8` | `#111923` | Hero 后的页面基底；保留冷色但降低卡片反差 |
| 阅读面 `sheet` | `#FFFFFF` | `#1A2733` | 正文底面、代码与图表的承载层 |
| 主墨 `ink` | `#192B3A` | `#ECF2F5` | 正文、主要标题 |
| 次墨 `muted` | `#526473` | `#B4C3CD` | 图注、辅助信息与引语 |
| 分隔 `rule` | `#DCE5EB` | `#3A4A57` | 必要的结构边界，避免处处画线 |
| 研究蓝 `signal` | `#2456B3` | `#A3BDFF` | 链接、焦点、目录当前位置 |

这是一套面向芯片图像、技术截图与长篇阅读的冷静色板，不采用温奶油色、陶土色、荧光绿或纯黑大面积对比。具体文本/背景组合在实施时必须达到 WCAG AA 的普通文本对比度；弱化文字、焦点环和暗色链接分别实测，不能仅凭色值表认定合格。

#### 字体体系

| 角色 | 提议字体 | 原因与边界 |
| --- | --- | --- |
| 正文、导航、图注、中英文标题 | `IBM Plex Sans`（拉丁）＋`Noto Sans SC`（简体中文） | Plex 的字形有技术文档气质；Noto Sans SC 覆盖中文技术叙述。整站共用这一套字族，避免文章/导航不同声线。使用按 Unicode 范围拆分的 WOFF2 子集和系统回退。 |
| 代码与数据 | 保留现有等宽回退；如本地基准显示字形不稳，再评估 `IBM Plex Mono` | 代码必须按字符对齐，独立于正文。避免仅为视觉统一多下载一套字体。 |
| PDF 打印 | 保留现有宋体优先回退，并依据打印样张决定是否与屏幕字体靠拢 | 屏幕滚动与纸张分页的需求不同，不让自托管网页字型妨碍 PDF 导出。 |

两套字体的许可与来源：[IBM Plex 官方仓库](https://github.com/IBM/plex)、[Google Fonts Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc)。字体以 Google Fonts 提供的 Unicode 子集 CSS/WOFF2 作为自托管文件，并随站点保存各自许可证；没有添加字体预加载。

**字阶初始规格**：桌面正文 17px、行高约 1.78；手机正文 16.5–17px、行高约 1.72–1.78；正文 H1 30–34px、H2 25–28px、H3 21–23px、H4 18–19px；图注 13–14px；代码 13–14px。正文主字重 400，强调 600，标题 600/700。中文不做负字距；拉丁大标题可略收紧。对超长 IELTS 段落与英文技术文本分别检查行长和实际换行，不机械地把所有块设为同一个 `ch` 值。

#### 布局方案比较

方案 A：直接把现有 `72ch` 缩窄，其他块仍跟随文章卡片宽度。实施少，但段落、图片、表格和标题的对齐关系仍可能松散。

```text
Hero（居中标题）
┌────────────────────────文章卡────────────────────────┐ 目录
│ 段落 max-width:72ch                                  │ 当前位置
│ 图／代码／表格使用各自宽度                           │
└──────────────────────────────────────────────────────┘
```

方案 B（采用）：在文章卡片内建立**阅读轴**与**媒体轴**。文字左对齐、文章容器整体居中；阅读轴约 40–43rem，宽媒体轴约 100% 的卡片可用宽度。手机合并为单轴并保持 18–22px 安全边距。标题、普通段落和列表沿阅读轴，图像、表格、代码、宽公式由内容需要选择媒体轴；不做强制两端对齐。

```text
            Hero：现有图像与标题
┌────────────────────正文卡片────────────────────┐  ┌─目录─┐
│    阅读轴：标题／段落／列表／引语             │  │ ● 当前│
│    ─────────────────────────────────          │  │   子级│
│    媒体轴：图片／代码／表格／公式             │  └──────┘
└──────────────────────────────────────────────┘

手机：
┌──────────────────────────┐
│  标题／段落／列表        │
│  图片／可横向滚动代码    │
└──────────────────────────┘
```

采用 B 的原因是本站实际包含大量操作截图、表格与技术代码，单一宽度会牺牲阅读行长或媒体辨认度。普通正文坚持左对齐；居中只用于 Hero、单张图片与图注，不使用两端对齐造成中英混排空洞。

## 4. 详细实施步骤

### 阶段 0：冻结阅读基准并定位瓶颈

**动作**

1. 保存当前分支、提交、未提交改动和两篇样本的路径；记录浏览器版本、系统缩放、分辨率、设备像素比、主题和字体是否加载。开发构建与生产预览分别采集，正式比较优先使用生产构建。
2. 对 390px、768px、约 1440px 的浅/深主题截图：Hero 到正文交界、第一段、普通标题、长列表、图片与图注、代码/表格、末尾、目录当前项。用相同内容和滚动位置采集改造后图。
3. 在 NAND 图文文和 IELTS 超长文各做冷缓存/暖缓存的连续滚动记录；分开测试自然滚轮、拖动滚动条、目录点击、正文 `#hash`、浏览器后退。记录 Performance trace 的长任务、布局/绘制峰值、帧间隔和资源瀑布图。**不要把 Lighthouse INP 当作滚动帧率**。
4. 记录 `scrollHeight`、标题与图片数量、字体请求大小和实际渲染字体；对比首张正文图是否与 Hero 抢优先级。若卡顿只在某个浏览器或图片段出现，按证据缩小变更。
5. 为字体和配色制作一页临时样张，至少包含中文长段、中英混排、英文长段、公式、表格、代码、纯 URL、深色主题。样张仅用于评估，不进入公开导航。

**产物**：基准截图、浏览器轨迹与简短问题清单。**退出条件**：能明确指出哪些不顺滑来自滚动规则、哪些来自渲染/资源；没有实测依据的优化标为待验证。

### 阶段 1：字体资源与全站排版令牌

**涉及文件**：`src/styles/global.css`、`src/components/BaseHead.astro`；必要时新增 `public/fonts/` 与许可文件。

1. 核验并下载官方字体的网页格式，只纳入实际用到的字重/字形；登记版本、来源、许可证、文件体积。优先自托管以避免当前 Google Fonts `@import` 的额外样式请求链；若中文字体首屏代价明显，调整分片与 `unicode-range`，不把整套 CJK 字库作为一个首屏高优先级文件。
2. 建立 `--font-reading`、`--font-interface`、`--font-code` 与字号、行高、阅读宽度令牌。阅读与界面可共享同一字体栈，但要分别控制字号和字重。先处理 `body` 与通用标题，再逐项查找 `Outfit`、`Plus Jakarta Sans` 的硬编码，避免表头或 About 页面继续混用旧字体。
3. 配置 `@font-face` 的 `font-display`、明确回退栈与必要的字体度量调整；只在有实测收益时预加载关键 WOFF2。对中文、英文、混排逐一验证字体加载前后的换行和 CLS。
4. 保留系统字体作为离线与缺字回退；检查简体中文、英文符号、粗体、数字、斜体和特殊技术字符是否发生不自然的替换。不要全站强制 `font-synthesis:none`，除非已提供真实所需字重。
5. 全站快速回归导航、首页 Hero、归档卡片、标签、关于、搜索弹窗，修正因新字体引发的换行和按钮宽度变化；不借此扩大布局重设计。

**退出条件**：截图中没有明显的字体拼接感；首屏字体请求与位移有记录；弱网/字体失败时仍可读；许可完整。

### 阶段 2：正文渲染与阅读节奏

**涉及文件**：主要是 `src/styles/global.css`，少量布局容器规则在 `src/layouts/BlogPost.astro`。

1. 将文章专用样式集中到明确的 `.article-reading`/`.prose` 命名空间，令牌化阅读轴、媒体轴和段距。避免依赖 `main`、`h2`、`blockquote` 等全局选择器覆盖所有页面；打印样式仍以 `@media print` 为最终控制层。
2. 修正首个可见 Markdown 元素的上边距；保留 Hero 与内容卡片的现有交叠，但让读者在卡片开始后直接看到标题/导语。若正文以图片、列表或引语开头，也需同样有效。
3. 使用清晰的层级：正文 H1 作为文章内主标题，H2 承担主要章节分隔，H3/H4 用字号与空间体现从属；不在所有标题下重复画底线。标题上方留白应显著大于下方，连续小标题则收紧。已有文章内 H1 不删除，也不改 Markdown slug。
4. 段落用统一的“行高＋段距”节奏；相邻列表、列表内段落、嵌套列表分别设置，避免长文中每一项都像独立卡片。中文引语取消无理由的统一斜体，保留清晰左缘和较柔和的底色；英文引用可按内容适当斜体。引语内的链接、加粗仍有足够对比。
5. 普通段落/列表限制在阅读轴；代码、表格、图像、Mermaid、块公式可以占媒体轴，但其边缘与标题起点仍有明确关系。长 URL/长代码只在所属容器换行或横向滚动，不撑开整页。
6. 技术截图移除“悬浮卡片”式大阴影和上浮放大；以更轻的边界和恰当的图注承载。图像灯箱仍由点击触发，图片缩放不影响正文几何尺寸。暗色主题图片滤镜应按真实文章判断是否仍需要全局生效，避免电路截图失真。
7. 代码块与表格降低额外阴影、模糊、位移，仅保留功能性边界、可见的复制/横滚提示。移动端代码复制按钮保持直接可见，焦点状态不依赖 hover。
8. 复查脚注、删除线、强调、内联代码、行内数学、块级数学与嵌套引用；实际内容尚未覆盖的格式用临时样张验证。正文颜色不得依赖浏览器默认 `rgb(var(--gray-dark))` 的无意继承。

**退出条件**：中英混排的行长舒适；正文标题和媒体有稳定对齐；NAND 与 IELTS 两篇样本都无横向页面溢出，技术图与代码仍可辨认。

### 阶段 3：滚动路径、目录与页面过渡

**涉及文件**：`src/styles/global.css`、`src/layouts/BlogPost.astro`、`src/components/TableOfContents.astro`、`src/scripts/toc/controller.ts`、`active-heading.ts`、`scroll-navigator.ts`、`src/scripts/scroll-restoration.ts`，必要时 `src/components/BaseHead.astro`。

1. 先移除 `#main-content` 的**全局** `scroll-behavior:smooth`，让程序化恢复与未显式指定行为的定位不再意外继承平滑；用户滚轮、拖动和触摸继续保持原生行为。目录点击与明确的页面锚点仍由现有 `scroll-navigator` 控制；`prefers-reduced-motion:reduce` 切换为即时定位。
2. 保留 `--header-height`、`--anchor-gap` 与 `scroll-margin-top` 的单一定位契约；统一目录链接、正文页内链接、直接打开带 hash 的 URL、搜索命中落点。对移动 Header 高度变化和字体加载后的标题位置重新检查。
3. 文章卡片不再作为一整块长内容持续变换或长期持有 `will-change`。首屏如果需要入场，只对小范围、短生命周期元素做一次轻量变化；优先试验静态正文加载。观察是否减少长文章滚动过程中的大图层与重绘。
4. 对文章页 `page-content` View Transition 做独立评估：若长页截图/动画引发明显停顿，缩小过渡对象或使用简短不位移的淡化，并保留 Header 与 Hero 的现有过渡。用实际跨页导航和返回对比，而不是直接全局删除转场。
5. 目录活动项保持即时反馈；把当前 `max-height:1000px` 的子树展开动画替换为不会在每次章节变化时造成明显重排的方案，或在长文中禁用该动画。允许目录自身滚动跟随，但不抢主滚动、焦点或触摸手势。
6. `active-heading` 已把滚动更新合并到 rAF，并缓存标题位置。只有 trace 证明 207 标题的刷新有可见成本，才进一步节流 `ResizeObserver`、合并布局测量或改变缓存失效策略；保留图片/字体加载后重新定位的正确性。
7. 如 trace 显示真正瓶颈来自超长 DOM，可做独立试验：以语义章节分组评估 `content-visibility:auto` 与合理的 intrinsic size。**不得直接加在整个 `.prose` 或每个段落上**；先验证目录、查找、hash、图片懒加载、复制、打印与历史恢复都不跳位，再决定是否保留。此项属于后置实验，不是默认改造。
8. 不引入 wheel/touch 事件改写器、惯性滚动库、强制 `scroll-snap` 或逐段 reveal；它们会改变用户习惯的滚动距离并增加维护成本。

**退出条件**：手动滚动始终可中断目录动画；锚点落点稳定；切页、后退、刷新恢复正确；长文滚动记录较基线改善，且没有新增长任务与显著视觉跳动。

### 阶段 4：链接语义与统一样式

**涉及文件**：`astro.config.mjs`、新增文章链接分类 rehype 插件及对应测试、`src/styles/global.css`；必要时 `src/components/Footer.astro`、`Header.astro` 的共享字体/焦点细节。

1. 在 Markdown/MDX 的 HAST 中给**静态可判定**链接分类：`#hash`、站内相对路径、同源绝对 URL、跨源 `http(s)` URL、`mailto:`/`tel:`、下载链接。避免使用简单的 `href^="http"`，它会把同源绝对 URL 当外链，也覆盖不了协议相对 URL。动态 MDX 属性无法在构建时判定时保留安全默认样式。
2. 正文链接共同规则：持续可见的下划线、适度离开字形的 underline offset、浅/深主题对比合格；hover 只改变颜色/下划线厚度，不推动文字或插入导致重排的内容；`:focus-visible` 有清楚轮廓，已访问状态保持可读。
3. **仅真实外链**增加小型外出符号，符号在 DOM 中标记 `aria-hidden="true"`，不覆盖原有可读链接文字，也不因符号使行高改变。标记表达跨站含义而非给每条链接装饰箭头。图像包裹的链接、空文本链接、自动生成脚注链接应按语义单独处理。
4. 文章外链默认继续在当前标签打开，以保留浏览器后退链路；若个别链接显式选择新标签，补 `rel="noopener noreferrer"` 与可读的新标签提示。现有 Header/Footer 外链新标签行为单独回归，不强迫与正文一致。
5. 页内目录链接的视觉样式与普通外链区分：目录依靠当前位置指示、正常文字色和焦点环；正文内 `#hash` 保留阅读用下划线但没有离站符号。链接点击后不能让标题被固定 Header 遮住。
6. `@media print` 中取消交互符号的干扰，保留可识别的下划线和必要 URL 展示策略；PDF 导出不丢失链接可点击性。

**退出条件**：同源/外链/锚点/邮件/下载/图像链接的分类测试通过；鼠标、键盘、触摸和打印状态可辨认；没有新增失效链接或强制新标签行为。

### 阶段 5：整合、回归和收束

1. 将临时比较样张与实验性 CSS/脚本移出公开构建，保留可复现的验收记录。
2. 清理重复选择器、无效旧字体声明、临时 `!important` 和不再用的动效令牌；检查 Astro scoped style、`:global()`、全局 CSS 和打印规则的优先级。
3. 运行 `npm run check`、`npm test`、`npm run build`；手动测试两篇真实文章及首页、归档、关于、搜索。对滚动/锚点/链接分类等纯逻辑边界补有意义的测试，不为每个 CSS 数值写镜像测试。
4. 输出前后截图、性能记录、字体资源体积、已知浏览器差异与回退方式。主观审美审核要问：是否还存在无意义的线、阴影、箭头、动效；删去最后一处多余装饰。

## 5. 验收矩阵与量化口径

| 场景 | 验收方式 | 通过标准 |
| --- | --- | --- |
| 自然滚动 | 两篇样本，在桌面滚轮/触控板及手机触摸连续往返 | 手势和页面运动一致，无滚动劫持；肉眼无重复卡顿，Performance trace 相对基线改善 |
| 帧稳定性 | 在相同设备/文章/缓存状态下比较 10 秒滚动轨迹 | 目标：绝大多数帧位于设备刷新预算内；不新增超过 50ms 的滚动相关长任务。若设备达不到，给出基线、改善幅度和主要剩余成本 |
| 布局位移 | 冷加载、字体切换、61 张图的逐步加载 | 页面视觉 CLS 目标 < 0.1；图像前后段落和当前阅读位置不发生可见突跳 |
| 锚点位置 | TOC 点击、正文页内链接、直接 URL hash、搜索命中 | 标题顶端与 Header 安全间距误差控制在约 ±8px；重复跳同一目标结果一致 |
| 中断与减少动效 | 目录滚动中滚轮/触摸/键盘干预；开启 reduced motion | 立即交还控制；减少动效时无长距离平滑动画、整卡入场和持续目录动画 |
| 历史恢复 | 文章中部 → 另一页 → 后退/前进；刷新；跨文章 | `#main-content` 回到原阅读附近，不从 Hero 再缓慢动画到旧位置；不被初始 hash 覆盖 |
| 排版 | 390/768/1440px，浅/深主题，中文、英文、混排 | 正文行长稳定、标题层级清楚；整页无横向溢出；代码/表格各自可横向浏览 |
| 字体 | 字体成功、弱网延迟、字体请求失败 | 字符无缺失；回退仍可读；首屏字体切换不产生明显大段重排；字体来源与许可可追溯 |
| 外链 | 不同链接类型与键盘操作 | 分类准确；外链符号只在真正外链出现；焦点清晰；新标签提示与实际行为一致 |
| 图文 | NAND 文章前、中、末段及暗色灯箱 | 截图清晰、图注不贴图、图片不会在滚动时大幅改变占位；灯箱保持原图亮度 |
| 长文字 | IELTS 文章 207 标题、1,808 段落 | 目录不会频繁展开/收起造成抖动；章节跳转可用；复制、查找、打印不漏文 |
| PDF | 两篇文章各导出至少一次 | 打印头、标题编号、图片、代码、表格与页码正常；屏幕新增装饰不污染 PDF |
| 全站回归 | 首页、归档、标签、关于、搜索、深色切换、导航转场 | 字体风格一致，功能和原有路由正常，移动菜单与搜索不溢出 |

“丝滑”不能用 CSS 属性名证明。记录必须附带设备/浏览器与测试内容；滚动指标应结合轨迹与视觉检查，避免单独展示一个分数。若某项优化牺牲定位准确性或可访问性，即使帧率提高也不算通过。

## 6. 关键风险与处理顺序

| 风险 | 触发方式 | 处理原则 |
| --- | --- | --- |
| CJK 字体资源过大 | 全量文件进入首屏或多字重重复下载 | 先测网络；使用适当分片/范围、减少字重与预加载；必要时以系统回退守住加载体验 |
| 字体替换导致目录错位 | 字体加载改变行数与标题高度 | 保留 `document.fonts.ready` 后重测，验证初始 hash 与恢复；不要以固定像素猜位置 |
| 移除全局 smooth 影响其他页锚点 | 所有页面共用 `#main-content` | 逐页验证；只给确实需要的用户触发操作添加局部平滑逻辑 |
| 长文章过渡/整卡变换成本 | 169k px 文本长页进入或返回 | 先做 A/B 性能记录，优先降低文章页整卡动画和持久图层，再考虑更深的 DOM 优化 |
| `content-visibility` 造成跳位 | 懒布局与目录测量/打印冲突 | 保持后置实验，默认不启用；任何跳位立即撤回此优化 |
| 选择器互相覆盖 | `global.css`、Astro 局部样式、打印样式共存 | 明确文章命名空间与层级；检查 computed style，不靠尾部大量 `!important` 修复 |
| 链接标记误判 | 同源绝对 URL、协议相对 URL、图片链接、MDX 动态值 | 使用 URL 解析和测试样例；无法静态判定时不作“外链”断言 |
| 图片懒加载影响定位 | 未知尺寸图片在长文中后载入 | 本地图片维持宽高；远程图尽可能补尺寸；用真实图文文章观察位移 |
| 打印样式退化 | 屏幕字体与 `.prose` 规则改写 | 每阶段打印预览，不到最终阶段才发现 PDF 回归 |
