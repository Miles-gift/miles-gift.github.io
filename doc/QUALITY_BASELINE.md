# 阶段 7：首发质量与上线基线

> 验收日期：2026-09-11  
> 验收范围：公开站点、内容工作台、自动部署与公开数据边界

## 1. 阶段目标

把“页面能打开”提升为可重复验证的首发基线：每次发布都检查类型、内容、站内链接、SEO、隐私边界与关键产物；同时用桌面和移动视口确认导航、字号、分类栏、主题及键盘交互。

## 2. 本阶段实现

### 2.1 自动质量门禁

- 根命令 `pnpm quality` 串联公开站点与 Studio 的 TypeScript 检查、品牌分享图生成、内容预检、生产构建、Pagefind 索引和生成站点检查。
- `script/check-public-build.mjs` 扫描全部生成 HTML，检查语言、标题、主内容、H1、canonical、Open Graph、JSON-LD、图片替代文本、重复 ID、站内链接和页面文件是否对应。
- 检查器会拒绝本地绝对路径、密钥特征、证件号码特征、已移除栏目以及 RSS、隐私、版权、源码等旧入口重新进入公开产物。
- GitHub Pages 工作流在构建前执行类型检查，在上传前执行同一套公开站点检查。
- 部署完成后由独立任务访问首页、文章、资料库、旅程、关于、sitemap、robots 与分享图，避免只构建而未验证线上结果。

### 2.2 SEO 与分享

- 每页具有唯一 canonical、description、robots、Open Graph 与 Twitter Card。
- 内容详情输出 `BlogPosting` JSON-LD 和发布日期/修改日期；栏目页输出 `WebSite` JSON-LD。
- 搜索和 404 明确为 `noindex,follow`。
- `sitemap.xml` 覆盖核心栏目、公开内容、主题页与标签页，共 78 个 URL。
- `robots.txt` 允许抓取并指向站点 sitemap。
- 自有分享图 `public/brand/yoyo-social-card.png` 为 1200 × 630，同时保留可维护的 SVG 源文件和生成脚本。
- RSS 继续按最终信息架构要求保持移除。

### 2.3 视觉、交互与无障碍

- 桌面 1440 × 900：首页与资料库无横向溢出，五项主导航完整显示并固定在视口顶部。
- 移动 390 × 844：首页和资料库无横向溢出；首页 H1 为 56.8 px，资料库 H1 为 43.2 px，保留视觉辨识度且不再压迫内容。
- 资料库分类/搜索带使用普通文档流，向下阅读时自然离开视口，不悬停在屏幕中央。
- 移动菜单显示五项主栏目；Esc 可关闭菜单，`aria-hidden` 与 `aria-expanded` 同步，并把焦点送回菜单按钮。
- 深色主题视觉与颜色切换正常；页面控制台没有警告或错误。
- 所有页面由生成产物检查图片 alt、主内容、H1 与重复 ID；系统“减少动态效果”规则继续生效。

说明：上述移动端结果来自精确的 390 × 844 浏览器视口。iPhone Safari 与 Android Chrome 的物理设备触控、旋转和系统字体差异无法在当前桌面环境内代替用户完成，作为发布后的设备复核项保留，不阻塞静态站点上线。

### 2.4 性能与字体策略

- 公开产物由约 43 MB 降至 8.9 MB，减少约 79%。
- 字体文件总量由约 35 MB / 914 个降至约 1.8 MB / 91 个。
- 单个最大公共 CSS 从约 947 KB（gzip 437 KB）降至约 41.5 KB（gzip 约 8.9 KB）。
- 中文标题改用 macOS/iOS、Windows 常见的系统楷体栈；正文使用系统宋体栈；英文标题与数字继续自托管 EB Garamond，代码继续使用 JetBrains Mono。
- 这一选择保留“手写批注 + 编辑排版”的气质，同时避免为中文全字库下载数十 MB 资源。

### 2.5 内容工作台

- Studio 生产构建：CSS 18.96 KB（gzip 4.92 KB），JavaScript 25.28 KB（gzip 9.84 KB），总产物约 52 KB。
- 冒烟测试覆盖四类内容的创建、保存、发布预检、版本冲突防护、真实图片格式校验、WebP 转码与可恢复删除。
- 概览、列表、四类标识与 Markdown 实时预览均通过自动界面断言。
- 测试内容及附属图片完成后全部移入 `.trash/cms/`，没有混入 36 条真实公开内容。

## 4. 验收中发现并修复的问题

1. 旅程详情曾把 `education`、`service`、`award` 等类型标签渲染成不存在的标签页，生成检查发现 21 条断链；现改为不可点击的事实标签。
2. 旧工具函数仍残留已删除的 `pages` 集合与过强的 i18n 非空假设；现已收窄类型并提供安全回退，根 TypeScript 检查恢复通过。
3. 中文完整字库带来不成比例的发布体积；改用系统中文字体栈后，公开产物减少约 34 MB，截图确认排版气质和层级仍然成立。
4. 搜索与 404 原先可能被索引；现明确设置 `noindex,follow`。

## 5. 公开数据边界

- 公开产物不包含本地绝对路径、密钥特征、身份证件号特征或证书原图。
- 证书编号、二维码、学号、队友和教师姓名继续不进入网站。
- 资料库仍发布用户授权的 Markdown 原文；修复只涉及展示格式和不可公开本地图片路径，不替用户总结正文。
- 当前无评论、统计、newsletter、远程后台或第三方追踪脚本，因此不产生新的访客数据收集。

## 6. 发布与回滚

- 发布链路：功能分支 → `main` → GitHub Actions 类型/构建/公开产物检查 → Pages 部署 → 线上核心路径检查。
- 首发标签以远端完整部署成功的版本为准；若仅 Release 打包成功而 Pages 未通过，不作为上线完成依据。
- 若线上异常，优先回退到 `baseline/stage-6`，或恢复首发标签对应提交并重新触发部署。
- 日常内容发布见 `doc/PUBLISHING_SOP.md`，冲突、误删和构建失败处理见 `doc/CMS_RECOVERY.md`。
