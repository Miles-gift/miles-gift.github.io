# 本地 CMS 阶段 4：一键发布与 GitHub 状态

## 本阶段交付

- 新增文章发布队列：文章必须明确勾选“加入发布清单”；私有草稿不会自动进入公开仓库。删除文章仍以本地待删除状态进入发布清单。
- 新增发布页，列出将要新增、修改、删除的文章、博客设置和图片，并展示阻塞原因。开始推送前再次显示目标 `origin/main` 并请求确认。
- 新增发布服务：只接受指定的 Miles-gift GitHub `origin` 和当前 `main` 分支；先 fetch，远端领先时只做 fast-forward；拒绝其他工作区改动、ahead 提交、文章基线冲突、不安全路径及草稿公开。
- 发布前备份受影响文件，原子应用清单中的内容，依次运行 frontmatter 校验、Astro 检查、测试和生产构建。任何检查失败都会尝试恢复，保留本地 CMS 工作区与备份。
- 只暂存本次 CMS 清单中的路径，不使用 `git add .`；提交并推送被拒时不 rebase、不强推，并保留本地提交及待发布工作区。
- 以异步 Git/npm 子进程执行发布，使状态 API 能返回预检、fetch、应用、检查、提交、推送等阶段。推送后持续查询对应 GitHub Actions，直到部署进入终态，并抽查博客首页、RSS 和已发布文章。
- 部署工作流按仓库中的非草稿 Markdown/MDX 文件动态校验文章 URL，删除文章后不会继续检查被删除的页面。

## 范围说明

本阶段未从当前 CMS 实施分支向 GitHub `main` 执行真实发布。CMS 发布入口在非 `main` 分支会被拒绝；认证失效和断网不在真实主站发布流程中人为触发，远端推送拒绝由隔离本地 Git fixture 模拟。正式站点发布入口需在阶段 5 合并后从 `main` 使用。
