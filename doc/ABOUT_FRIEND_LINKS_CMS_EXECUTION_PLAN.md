## 4. 视觉设计：从现有网站延伸

### 4.1 设计定位

这是以个人学习、电子科学与集成电路方向长文为主的博客。About 的主角仍是作者；友联承担“从作者出发，访问朋友的网站”的次级导航功能。推荐以一个安静的“朋友名录”区块承接个人简介：名字醒目、域名清楚、信息左对齐，体量明显小于个人资料卡。

唯一的识别点是与作者圆形头像呼应的友站头像；未设置图片时继续显示小型字母圆标。无需芯片线路背景或科技装饰，学科身份已经由个人简介表达。

### 4.2 核心颜色 token

下面六种颜色均来自现有全局变量，代码中使用变量名，不复制成友联专属硬编码色值。

| 角色 | 变量 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- | --- |
| 页面背景 | `--color-bg` | `#f4f5f6` | `#0f1117` | 承接 About 背景 |
| 内容表面 | `--color-surface` | `#ffffff` | `#1a1d28` | 友联容器 |
| 强文字 | `--color-text-strong` | `#222222` | `#eef0f4` | 标题和站名 |
| 次文字 | `--color-text-secondary` | `#666666` | `#9aa0a6` | 简介和域名 |
| 边界 | `--color-border` | `#eeeeee` | `#2d3244` | 外边框与条目分隔 |
| 强调色 | `--accent` | `#2337ff` | `#7b8cff` | 焦点与交互反馈 |

不把当前 `--color-text-muted` 用于必读的小字号域名，特别是暗色模式；正式实现测量实际对比度，普通文字目标至少 4.5:1，焦点与关键图形至少 3:1。

### 4.3 字体与尺度

- 全部继承 `var(--font-ui)`：IBM Plex Sans、Noto Sans SC 与系统中文回退字体。
- 友联标题：建议 `clamp(1.35rem, 2vw, 1.6rem)`，600 字重，行高约 1.3。
- 站名：建议 1.05–1.15rem，600 字重，行高约 1.4。
- 简介：建议 0.95rem，行高 1.65；宽屏每条不超过约 45ch。
- 域名：建议 0.875rem，普通 UI 字体，不使用代码字体或全大写标签。
- `rem` 随现有根字号变化，必须在实际页面核对视觉像素大小，而非机械套用。
- 名称和简介允许换行；不用单行省略隐藏关键名称。

### 4.4 两个布局方向与取舍

方向 A：每位朋友一张浮起的小卡片，双列排列。容易实现，但会与主资料卡竞争，只有两条数据时也容易像通用产品推荐模块。

```text
个人资料卡
[独立阴影卡：朋友 A]  [独立阴影卡：朋友 B]
```

方向 B（选定）：一个低层级表面内排列两个条目，沿用个人卡外轮廓与内容对齐；条目以间距和分隔组织信息，不各自叠加阴影。

```text
宽屏：与 profile-card 左右边缘对齐
┌─────────────────────────────────────────┐
│               现有个人资料              │
└─────────────────────────────────────────┘

友联
┌────────────────────┬────────────────────┐
│ (M) Motues         │ (Z) zgzlcc.github.io│
│     Like River!    │                    │
│     motues.top     │     zgzlcc.github.io│
└────────────────────┴────────────────────┘

移动端：16–20px 内容内边距
友联
┌──────────────────────────┐
│ (M) Motues               │
│     Like River!          │
│     motues.top           │
├──────────────────────────┤
│ (Z) zgzlcc.github.io      │
│     zgzlcc.github.io      │
└──────────────────────────┘
```

如站名本身就是域名，视觉上可仅显示一次，避免第二条重复；链接可访问名称始终保留完整站名。域名由规范化 URL 派生，不额外存储一份。

### 4.5 布局与交互细节

- 区块置于 `.about-container` 内的 profile-card 后面，避免创建第二个 `stats-card`。
- 与个人资料间距建议 32–40px；标题至名录间距 16px。
- 大于 720px 使用两列；720px 及以下使用一列。新增条目按数组顺序逐行排列，奇数最后一项不拉伸成特殊大卡。
- 每位友联单独成卡片，卡片之间桌面留 16px、移动端 12px；圆角 18px，并保留 About 的主题表面与边框。
- 每条内部留白 16–20px；头像约 58px；`min-width: 0`、`overflow-wrap: anywhere` 防止长域名撑破布局。
- 整条用一个 `<a>`，不在链接内嵌套按钮或链接。外链可新窗口打开，设置 `rel="noopener noreferrer"`，并提供“新窗口打开”的可访问说明。
- hover 轻微抬升卡片、放大头像并增强阴影；键盘焦点保留明确轮廓；不添加粒子或循环动画。
- 入场错峰不超过 350ms；所有动画与过渡均服从 `prefers-reduced-motion`。
- 使用 `section` + `h2` + `ul/li`；头像为装饰图像，链接名称由站点名称提供。
- 无可见友联时，公开页不渲染整个区域；CMS 则显示“还没有友联，添加第一位朋友”。

### 4.6 设计自审与修订记录

1. 初版采用单个名录表面；用户反馈要求每位友联明确分隔后，修订为间距独立卡片。
2. 不新增 02 编号，因为友联不是个人介绍后的第二步。
3. 不额外添加英文眉题、箭头文案和宣传性副标题；“友联”已能说明用途。
4. 不引入新字体或新主色；本任务的辨识度来自现有作者头像、字体与名录比例的连续性。
5. 用户指定头像后，先从友站定位图片源，再本地托管以稳定加载；未来记录可在 CMS 填写 HTTPS 图片地址或本站友联图片路径。
6. 动效只反馈页面进入、悬停和键盘焦点；避免持续或强烈运动，并保留减少动态效果支持。

## 5. 数据层与校验约定

### 5.1 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/data/friend-links.json`（新增） | 公开版本数据，是生产构建的唯一友联数据源 |
| `src/lib/content/friend-links.ts`（新增） | 共享类型、纯校验与规范化、展示数据派生 |
| `tools/local-cms/friend-links.mjs`（新增） | 私有文档读取、基线、原子保存及版本冲突 |
| `.local-cms/friend-links.json`（运行时创建） | 私有工作副本，不进入 Git |
| `src/components/FriendLinks.astro`（新增） | 语义渲染和局部样式 |

共享 TypeScript 模块应只含运行时可擦除类型与纯逻辑，避免依赖 Astro 或 Node 文件 API。当前 CMS 用 Node `--experimental-strip-types` 启动，可参照已有内容模块导入模式验证兼容性。

### 5.2 字段规则

| 字段 | 规则 | CMS 形式 |
| --- | --- | --- |
| `version` | 固定为 1；未知版本显式报错 | 不展示 |
| `links` | 数组，建议上限 100 条；空数组有效 | 友联列表 |
| `id` | 唯一、稳定；新建使用 UUID；种子 slug 允许；限制长度与 ASCII 安全字符 | 内部字段，不随改名变化 |
| `name` | 去首尾空白后 1–60 字符 | 必填文本框 |
| `url` | 规范化后不超过 2048 字符；有效 http/https 绝对地址 | 必填网址框 |
| `description` | 字符串，去首尾空白后 0–160 字符 | 可选文本域，字数提示 |
| `enabled` | 必须是 boolean，新增默认 true | “在 About 显示”开关 |

额外字段默认拒绝；记录 id 不得重复；URL 规范化后的完全重复记录报错并定位条目。只对安全等价部分规范化：主机大小写、默认端口、根路径；不随意删除子路径、查询参数或片段，不将同域不同页面强制视作重复。

### 5.3 地址输入体验

- CMS 可将没有协议的明确域名建议补为 `https://`，保存前显示结果。
- 对末尾中文句号等可疑标点，提示“网址末尾包含中文标点，请确认后移除”，不静默改写所有链接。
- 此次种子地址已明确纠正为 `https://zgzlcc.github.io/`。
- 拒绝 `javascript:`、`data:`、`file:`、协议相对地址和包含用户名密码的 URL。
- 服务端重复校验；前端提示不替代服务端校验。
- 名称/简介均作纯文本渲染；Astro 自动转义，CMS 使用 `textContent`，不拼接输入到 `innerHTML`。
- 保存不请求目标网站；站点暂时不可达不阻止保存、构建或发布。

### 5.4 私有文档与冲突

建议私有 envelope 包含 `version`、`data`、`baseData`、`baseHash`、`baseContent`、`baseHead`、`savedAt`、`revision`。

- 首次读取时无私有文档就读取公开数据；已有私有文档则恢复编辑内容。
- 首次保存固定公开基线，后续保存不得悄悄更新该基线来掩盖冲突。
- `baseHash` 检测公开文件变化；`revision` 检测两个 CMS 标签页相互覆盖，二者不能混用。
- PUT 带 `expectedRevision`；版本不符返回 409，保留当前编辑内容，并提供重新读取与手动比对路径。
- 初次无私有文件也应返回确定的 revision 标识；保存过程按资源串行化，保证“比较版本—写入”不可被并发请求穿插。
- 保存采用临时文件加 rename，延续 0700 目录/0600 文件模式与符号链接检查。
- JSON 损坏/未知版本显示可定位错误，不以空数组覆盖原数据。
- 默认无修改不生成发布变化；规范化比较保留数组顺序，使排序也能进入清单。

## 6. 本地 CMS 交互与接口

### 6.1 页面结构

```text
文章    博客设置    友联    发布

友联管理                            [添加友联]
添加的网站会显示在 About 页面。

Motues          motues.top           显示
[编辑] [上移] [下移] [隐藏] [移除]

zgzlcc.github.io                    显示
[编辑] [上移] [下移] [隐藏] [移除]

状态：有未保存的修改
                     [预览 About] [保存到本机]
```

- 复用 `.cms-card`、`.cms-button`、`.cms-field` 等既有视觉规则；新增样式使用 `.cms-friends-*` 命名。
- 编辑使用列表内展开表单，移动端单列；一次展开一条即可，不额外引入模态层。
- 点击“完成编辑”只更新当前编辑缓冲；“保存到本机”持久化整份名录，文案明确区分。
- 上移/下移提供键盘可用按钮，首/末项禁用对应方向；首版不做拖拽依赖。
- 隐藏记录仍可编辑与排序，CMS 显示“已隐藏”。移除后提供撤销，保存前可以恢复。
- 隐藏、排序、移除同样触发 dirty 状态；新建取消不残留空记录。
- 切换标签时保留内存中的未保存内容；整页刷新/关闭复用离开提醒。
- 网络或校验失败保留输入，定位错误字段；成功状态通过 `aria-live` 反馈。
- 保存期间禁止重复提交。若允许继续输入，必须只把已发送快照标为已保存，不能误清除后续编辑的 dirty 状态。

### 6.2 拟新增接口

| 接口 | 用途 | 结果与约束 |
| --- | --- | --- |
| `GET /api/friend-links` | 读取公开或本地版本 | 返回 data、local、savedAt、revision、基线状态 |
| `PUT /api/workspace/friend-links` | 保存整个名录 | body 为 data、expectedRevision；服务端取得必要基线；成功返回新 revision |
| `POST /api/preview` | 现有接口增加 `/about/` | 保存成功后叠加私有友联并打开 About |
| `GET /api/publish/summary` | 现有清单增加友联变化 | 显示新增/修改/移除/显隐/排序摘要 |
| `POST /api/publish` | 现有发布链集成 | 仍使用已有锁、校验、备份、检查、提交、推送流程 |

错误建议：400 数据校验；403 来源/session 不合法；409 版本冲突或发布占用；500 文件操作异常。前端应显示可理解的中文信息，内部堆栈只留在本地日志。

### 6.3 一次新增的完整用户路径

1. `npm run cms`，打开本地管理页，进入“友联”。
2. 点击“添加友联”，填写名称和网址，可选填写一句介绍。
3. 完成编辑，条目加入列表；默认显示在 About。
4. 点击“保存到本机”，状态显示“已保存到本机，公开网站尚未变化”。
5. 点击“预览 About”，在隔离 Astro 页面验证真实效果。
6. 进入“发布”，核对友联变化及其他既有待发布内容。
7. 使用既有发布动作完成检查与发布；区分“已推送”和“已部署”。

预览发现未保存编辑时先执行保存，失败则不打开旧快照冒充最新效果。弹窗被拦截时给出可点击预览链接。

## 7. 预览、发布与恢复的关键集成

### 7.1 预览

必须同时处理以下位置：

1. `createPreviewManager` 参数加入 `friendLinksPath`。
2. 路径白名单精确允许 `/about/`，仍拒绝任意路径和外部 URL。
3. 仅对单篇 `/blog/{slug}/` 执行文章文件存在性检查，避免把 About 当文章。
4. 在隔离副本中写入本地友联 JSON；不改项目真实公开文件。
5. 就绪探测至少请求目标 pathname，确保 About 本身编译成功，不能只以 `/blog/` 返回 200 判定成功。
6. 保留现有临时目录、端口、进程清理机制；失败时同样清理。
7. 文章预览、博客设置预览继续有效；私有友联不污染真实开发服务器。

### 7.2 发布

以独立 `friendLinksDocument` / `friendLinksChange` 接入，不把它伪装成博客设置。

1. 路径安全检查纳入 `src/data/friend-links.json`。
2. inspect 阶段读取私有文档，对比基线，产生独立变化。
3. 清单至少展示“更新友联”，并可展开看每项变化；仅顺序变化也必须可见。
4. 只改友联、没有文章或博客设置变化时也允许正常发布。
5. changedPaths、备份列表、精确暂存路径包含友联 JSON。
6. 应用前再次验证数据与基线；原子写入并记录应用后哈希，供恢复判断。
7. 运行现有完整预发布检查，不因本次只改 JSON 而跳过构建。
8. 友联单独发布时使用清楚的提交说明，不能仍显示“update blog settings”。
9. 提交前失败恢复公开 JSON，保留私有编辑；推送失败保留提交与私有文档，沿用现有可恢复状态，不强推。
10. 成功推送后归档实际发布的友联私有文档；归档失败应提示，而非伪装成功清理。
11. 发布期间友联写接口返回 409，防止保存的新版本被发布归档误删；如果实现改用 revision 比较归档，也必须有对应竞态测试。
12. 部署核验纳入 `/about/`，检查响应及预期链接；仅 HTTP 200 不能证明新数据已经上线。

开发代码本身应先完成正常代码交付，之后 CMS 内容发布才有干净工作树可用。不得为了绕过发布阻塞而自动 stash、删除其他改动或扩大暂存范围。

### 7.3 状态区分

| 状态 | 对用户的表达 | 数据所在位置 |
| --- | --- | --- |
| 编辑未保存 | 有未保存的修改 | 浏览器内存 |
| 本地保存 | 已保存到本机，尚未发布 | `.local-cms/friend-links.json` |
| 预览成功 | About 预览已生成 | 系统临时目录 |
| 检查失败 | 显示具体错误，编辑内容已保留 | 私有文档及备份 |
| 已推送 | 已推送，等待部署 | Git 远端及归档 |
| 部署失败 | 推送成功，但部署失败 | 保留提交信息供排查 |
| 已部署且核验成功 | About 友联已更新 | 公开网站 |
